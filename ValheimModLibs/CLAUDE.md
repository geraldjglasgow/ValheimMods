# CLAUDE.md - ValheimModLibs

Shared libraries for Valheim BepInEx mods, extracted from Elite Creatures Reborn, the reference consumer (`../EliteCreaturesReborn`, 2026-09-12). FeastMaster, Lockstep, OpenKeep, PackPanel and ShipConfig consume them as well.

## Layout

- `Directory.Build.props`: net48, nullable, game and BepInEx paths. All projects inherit it.
- `Charter/`: our own server-to-player configuration binding, written clean-room from `Charter/SPEC.md`. `Charter` (the per-mod object: `Clause`, `Binding`, `IsBound`, `IsAuthor`, `MayAmend`, `IsSteward`, `Install`), `Clause<T>` (a registered ConfigEntry with `AuthorValue`/`OwnValue`), `Article<T>` (a pushed value that is not an entry: `Assign`, `Changed`; ordinary articles travel only while bound, `standing: true` ones always). Internals, one class each: `Ledger` (registration), `PushBody`/`Fragmenter`/`FragmentAssembler` (wire), `Publisher`/`Courier` (author side), `Receiver` (player side), `ChangeRouter` (what an entry edit means on each side), `Amendments` (steward edits), `Stewardship` (admin list), `ReadOnlyTags` (configuration manager tag), `Family`/`FamilyEntry`/`FamilyCheck`/`FamilyRpc` (the one-screen join check across all our mods), `RefusalScreen`, `ConsoleCommands` (`charter`), `GameHooks`/`Ticker`. See `Charter/README.md` for the decisions.
- `BundlePrefabs/`: a mod's own models in the game. `EmbeddedBundle.Load(assembly, name)` loads the embedded
  `<name>.windows` / `<name>.linux` asset bundle for the running platform (dedicated servers run the Linux player);
  `PrefabBench.Copy(prefab, name)` makes an inactive copy (no Awake, no ZDO) to build on; `NetPrefabs.OnSceneAwake` /
  `Register` add prefabs to ZNetScene after its Awake on every peer; `ItemPrefabs.Register` keeps item prefabs in every
  ObjectDB; `GameMaterials.Borrow` / `Apply` dress a model in the game's own materials, so no game texture ships in a
  bundle; `GameMaterials.Dress(game, placeholder)` is a copy of a game material wearing a placeholder's own baked
  albedo and normal map, and `GameMaterials.Plain` strips the game maps that fit only the game model's UVs;
  `ModelBounds.In(model, space)` measures an inactive model's meshes; `CreatureBody.Wear` puts a workshop body made on
  a game skeleton onto a copy of that creature; `BundleEffects` dresses a workshop particle effect in the game's
  particle shaders and `EffectTint` recolours any effect copy; `SfxPrefabs` makes a mod's sound prefab from a game
  one with the bundle's clips (or the game's own clips at other settings). Bundles come from `../../ValheimAssets`.
  Consumers: EliteCrafting (the rune tablets), EliteCreaturesPack (the crypt mimic, the greydwarf slinger, the rime giant, the kraken and its loot),
  PackPanel.
- `LocalEffects/`: `LocalEffect.Attach(prefab, parent, position, endless, density)`, `Flash`, `FlashWhole`,
  `FlashScaled` (every part resized by its own numbers, `ScaleParts`, whatever its scaling mode), `Sound` and
  `SoundOnly` (an effect's own sound at a volume, nothing of it drawn) make local
  copies of the game's effect prefabs: instantiated with `ZNetView.m_forceDisableInit` (never ghost init,
  which registers a ZDO that ZNetScene then spawns as a networked copy on every peer), `Aoe`, `Projectile`,
  `ZSyncTransform` and `ZNetView` removed, colliders off; `density` 0 to 1 thins particles and dims lights, 0 spawns
  nothing, sounds are never thinned (`CloneParts` does the making and stripping). Consumers: EliteCreaturesReborn
  (its `CosmeticClone` passes the player's `Effect density`), EliteCreaturesPack (the Rime Giant's ice and avalanche).
- `PlayerGrid/`: PackPanel's published grid. `GridContract` (`Key` = `PackPanel.mainGrid`, `Write(player, width,
  mainRows, blockedCells)`, `Clear`, `TryParse`) is the one definition of the `width|rows|blocked` custom data value;
  `PackPanelLink` finds PackPanel by GUID in the chainloader (`Present`, `LaysOutInventory` = loaded and `1. Inventory /
  Enabled` on, `Entry<T>` for its config entries); `PackPanelGrid` reads the key only while `LaysOutInventory`
  (`TryRead`, `InSlot`, `BlockedCells`, and `TryMainRows`, which is false when PackPanel is on but the key cannot be read,
  for callers that must hold back rather than touch a slot). Consumer: EliteCreaturesReborn (Thieving). PackPanel's
  `Layout/GridContract` and OpenKeep's `Core/PackPanelGrid` and `Core/PackPanelLink` are the same code and are to move
  onto it.
- `EliteCraftingLink/`: EliteCrafting's public API (`EliteCrafting.Api.EliteCraftingApi`, spec in
  `EliteCrafting/features/api.md`) bound by reflection, so a mod never references EliteCrafting. `ApiBinding` finds the
  plugin by GUID (`com.EliteCrafting`) in the chainloader, the type by name in its assembly and checks
  `GetApiVersion()` against `Required` (1); until EliteCrafting is in the chainloader it looks again on every call, once
  found (or found too old) the answer is kept. `Endpoint<T>` binds one endpoint as a typed delegate
  (`Delegate.CreateDelegate`, by name, parameter types and return type; a missing one is logged once and stays null) and
  `Safe.Call` answers false, null or 0 when it is unbound or throws. The wrappers, by api.md section: `CraftingLink`
  (`Guid`, `Present`, `ApiVersion`, `PluginVersion`, `HasEndpoint`, `EndpointNames`), `CraftingClasses`,
  `CraftingInscriptions`, `CraftingItems`, `CraftingHooks`. Delegates handed in (classifiers, providers, filters,
  listeners) use game and BCL types only and pass through unchanged. Game types appear only in signatures
  (`ItemDrop.ItemData`, `Player`). A consumer loads after EliteCrafting (soft `BepInDependency` on `CraftingLink.Guid`)
  and registers the same things on every peer. Consumers: PackPanel (backpack class, Deep Pockets, worn
  pack provider) and EliteCreaturesPack (item levels, creature loot).
- `Hotkeys/`: a mod's hotkeys read one way. `Hotkey.Pressed(entry)` (main key down this frame; with modifiers all of
  them held and no other Shift/Ctrl/Alt, other keys such as W allowed; a single key only with no Shift/Ctrl/Alt held),
  `Hotkey.Held(entry)`, `Typing.Active` (chat focus, console, the game's text input, a selected `InputField` or
  `TMP_InputField`, or a window the mod registered with `Typing.AddWindow`, such as its YAML editor),
  `KeyNames.Short(shortcut)` (a key cap's text: `Z`, `Shift+Z`, `Ctrl+1`). Where a key works
  stays the mod's call. Consumer: PackPanel (Food Key, Mead Key); OpenKeep's `Core/Keys` is the same rules and is to
  move onto it.
- `WindowInput/`: a mod's own window treated like one of the game's while open. `GameWindow.Install(harmony)` (once;
  the patches go in once per merged copy, by hand, no attributes, so `PatchAll` never picks them up),
  `GameWindow.Add(isOpen, close)`, `AnyOpen`, `CloseOpen()`. While one is open: postfix `Player.TakeInput` false (no
  attacks, blocks, hotbar), postfix `PlayerController.InInventoryEtc` true (no mouse look), postfix
  `GameCamera.UpdateMouseCapture` (cursor shown and free unless the menu is up), postfix `ZInput.GetMouseScrollWheel`
  0 (no zoom; UI scroll views read the wheel themselves), prefix `Menu.Update` (Esc closes the window instead of
  opening the menu). Walking stays possible. Consumer: EliteCreaturesReborn (the death recap window); EarthWright's
  `Preview/PanelInputPatches` is the same rules and is to move onto it.
- `AreaLoading/`: arriving somewhere far, quicker. `AreaLoader.Install(harmony, report)` (once; two postfixes by name,
  `ZoneSystem.Update` and `ZNetScene.CreateDestroyObjects`, once per merged copy, no attributes) and
  `AreaLoader.When(busy)`: while a registered reason holds (on a connected, non-dedicated machine) the land around the
  player loads at 20 ms of the private `CreateLocalZones` per frame and the listed objects (`m_tempCurrentObjects`,
  read by reflection) are created at 15 ms per run through the game's `CreateObject` in its `ZDOCompare` order, only
  in zones whose land is in. `AreaSettle.Settled(point)`: on a server's client, the ZDO count in the point's 3x3
  sectors unchanged for 0.5 s. `QuickWait.Seconds/Speed/MapDistance`: waits that grow with distance, run as faster
  timers. Each mod's copy hurries only for its own reasons. Consumers: Wayfare (portal jumps), OpenKeep (respawns);
  moved out of OpenKeep's Homestead on 2026-10-04 when its quick portals went to Wayfare.
- `MapClicks/`: a click on a mod's own icon on the large map that leaves the game's pins working under it.
  `IconClick.Install(harmony)` (once; a prefix on `Minimap.OnMapDblClick` and a postfix on `Minimap.Update`, once per
  merged copy, by name, no attributes), `IconClick.Hold(action)` (from a left click on the icon: the action runs
  once the game's 0.3 s double click window has passed, and a double click drops it so the game places a pin there;
  it runs on a later frame, so it checks its own state again), `IconClick.PinUnderPointer(map)` (one of the player's
  placed pins under the pointer, as the game's private `GetClosestPin` within `PinInteractRadius` finds it: a right
  click on the icon lets the game remove it first), `IconClick.Drop()`. Consumers: Wayfare (portal icons while
  choosing a destination), OpenKeep (bed icons during the choice of bed).
- `ConfigReload/`: single file. `ConfigReloader.Setup(config, log)` saves the .cfg and polls it every five seconds for edits (no FileSystemWatcher: Mono on Linux fed it with the mod's own reads). `HoldSaves(config)` first in Awake turns SaveOnConfigSet off until `Setup` (BepInEx rewrites the whole file on every Bind otherwise; SyncedConfiguration does it in its constructor), and a reload saves once, not once per changed entry.
- `ItemCopies/`: `Copies.Apply(prefabName, write)` and `Copies.ApplyAll(write)` call the mod's write for the prefab's `SharedData` and for every live copy of it (`ItemDrop.s_instances`, the local inventory, the player's foods, the open container; each object once); `Copies.HookSpawns(harmony, onCopy)` runs the callback for new copies (postfixes on `ItemDrop.Awake` and `Inventory.AddItem(ItemData)`, installed once per merged copy). `CopyScan` reaches the private game members by reflection, `SpawnHooks` keeps the callbacks.
- `PlateColumn/`: the stat readouts on the inventory's player panel (`InventoryGui.m_player`) as one column of small brown boxes. The column is one container, `PlateColumn_boxes`, a direct child of the panel right after its `Bkg` (drawn above the panel background), anchored to the panel's top-right corner with its pivot at its own top-left, at (`Column.Left` 8, -`Column.Top` 6), `Column.BoxSize` (64) wide; a `VerticalLayoutGroup` (spacing `Column.Spacing` 6, upper centre, children keep their size) stacks its active children in sibling order and a `ContentSizeFitter` makes it as tall as they are, so every copy only has to put the boxes in rank order and Unity closes the gap a hidden one leaves. A `SeatWatch` on the container (one an older copy made may carry a `ColumnWatch` too) runs every frame the column is shown: it re-lays the column out the frame any box is shown, hidden or resized (a box's root has no Graphic to tell the layout group), seats a known box of another mod when it appears and pins the seated boxes. `Column.Arrange(gui)` (and `Column.Boxes(gui)`, which returns the container, null when the game's plates are missing) finds the game's armour and weight plates (walking up from `m_armor`/`m_weight` until the parent is the panel or the container), makes the container if needed, adopts every mod's box still a direct child of the panel (`PlateColumn_plate_*` made by an older copy, `OpenKeep_trash`) by moving the same objects in, seats the game's two plates (below), tips them, styles every member as a box (`BoxStyle`: 64x64, the largest child Image becomes `Skin.Box` sliced and stretched, the icon 30x30 at the top centre 6 px down, the text on a 22 px line 4 px above the bottom, 4 px in from each side, centred, TMP auto-size 10 to 16, no wrap; the game keeps writing its numbers into the same TMP objects), sorts members by rank into sibling order and lays out at once. `Column.Add(gui, PlateSpec)` makes (or finds) a mod's box, a copy of the restyled armour box (background, icon with the mod's sprite, optional emptied text) named `PlateColumn_plate_<rank:D4>_<id>` inside the container, tips it and re-arranges; the returned `Plate.Rect` is the box. Ranks: armour 100, weight 300; lower sits higher; `OpenKeep_trash` counts as 200. Each mod merges its own copy, so the scene is the only shared state. The game's plates never leave the panel: other mods find them there by name (`m_player.Find("Armor")`, `Find("Weight")`) to copy them or place their own boxes (Jewelcrafting, CurrencyPocket and OttoPay, TrashItems, Quick Stack Store Sort Trash Restock), and moving them into the container (OpenKeep 1.8.0 to 1.9.0, ECR 3.12.0 to 3.13.0, PackPanel 0.1.0 to 0.2.0) made Jewelcrafting's `InventoryGui.Awake` postfix throw, and with it every item drag and inventory close (GitHub #4, #5). Each gets a seat instead (`Seats`): an empty member `PlateColumn_plate_<rank:D4>_seat_<name>` with the plate's size and shown state, which the layout places, and the plate on the panel is pinned centre on centre over it and drawn after the container. Known copies other mods make of the armour box (`Guests`: `Jewelcrafting Synergy` 110, `Trash` 125, `CoinPocketUI` 200; only one with an `armor_icon` child) are seated the same way when they appear: moved, never restyled (TrashItems adds a clickable canvas to its can a frame later, which a restyle took for the background), stripped of the armour tip they copied, and their own override-sorting canvases lifted just above the inventory canvas (600; TrashItems' click layer sorts at 1 and otherwise loses every click to the column's clickable box backgrounds and PackPanel's stats panel). A plate an older copy moved into the container is moved back out. `Column.BoxesIn(boxes, list)` lists every box with each seat replaced by its plate, for a mod that dresses the boxes (PackPanel). The old `PlateColumn_mark_first`/`_last` markers are left alone and no longer made. `Skin` paints cached 9-slice sprites in code (no image files): `Skin.Panel` (dark line, bronze frame, dark line, #2E2014 fill at 0.94; radius 5, 32 px, border 8), `Skin.Cell` (#1F150D at 0.92, 1 px #5E4630; radius 4, 24 px, border 6), `Skin.Box` (#281B10 at 0.95, 2 px #7D5E3B; radius 5, 24 px, border 7), colours baked in (draw them white, sliced); `Skin.LabelColour` #D8C3A0 for captions. Every colour and shape is in `SkinPalette`. `EmbeddedSprite.Load(assembly, resource, name)` decodes an embedded PNG with mipmaps through the game's `ImageConversion.LoadImage`, found by reflection (its module targets netstandard 2.1, which net48 cannot reference). Tooltips are the library's own `PlateTip` (the game's `UITooltip` follows the mouse and cannot be pinned there): half a second after the pointer enters a box (anywhere on its background, which takes raycasts), `TipBox` shows an instance of `TipTemplate`: one copy, made once per session, of the game's inventory item tooltip prefab (`InventoryTooltip`, from the player grid's element prefab: a black 95% panel with Topic and Text) with a 2 px gold `Outline` border on the panel, kept under an inactive `DontDestroyOnLoad` holder (`PlateColumn_tiptemplates`) so it never wakes, made again if destroyed. `Column.DressTooltip(gui, tooltip)` hands the same template to one of the game's own `UITooltip`s as its `m_tooltipPrefab`, so a mod's tips elsewhere read like the boxes' while the game still shows and places them (another mod patching `UITooltip` can restyle those: in LocalTesting, with Epic Loot loaded, the skills panel's dressed tips came out as a black scroll box). `LinkTips.On(gui, text)` gives a TextMeshPro text tips on words: every `<link="id">` whose id got a topic and text through `Set` shows the same box 0.3 s after the pointer reaches the word, placed beside the word (`LinkBounds`: the link's characters on its first line) as a box's tip is beside its box, until the pointer leaves it; `Clear` before rewriting the text. It follows the pointer through UI pointer events (enter, move, exit), so it turns the text's `raycastTarget` on and needs no input API. A box tip is placed with its left edge 6 units right of the box, centred on the box's height, flipped left of the box or shifted vertically only to stay on screen; it never takes raycasts and goes when the pointer leaves or the panel closes. Another copy's tip is recognised by type name, and a `UITooltip` an older copy left on a box is removed on hover. `HudRow.Add(gui, PlateSpec)` puts a small copy of the restyled armour box (the mod's icon, an empty number line, no tooltip, no raycasts) in a column right of the minimap: the container `PlateColumn_hudboxes`, a child of `Minimap.m_smallRoot` (the framed square, which clips nothing; only its map child has a RectMask2D) anchored to its top-right corner, pivot top-left, `HudRow.Gap` (6) to the right, scaled `HudRow.Scale` (0.7), a top-left aligned `VerticalLayoutGroup` with a `ContentSizeFitter` and a `ColumnWatch`, sorted top to bottom by the same rank names; a row an older copy made (a `HorizontalLayoutGroup` under the map, ECR up to 3.13.3) is turned into the column when a newer copy looks it up. It hides with the small map. The game leaves the map only 40 units from the screen's right edge: PackPanel sizes the column (`HudRow.Container()`) and moves the map and the status effects left to make room. The mod writes its box's text itself (the game updates nothing there) and hides it with `SetActive(false)`. `HudRow.WeightIcon(gui)` is the game weight box's sprite. The column and the HUD row are PackPanel's look (the user's call, 2026-09-29: PackPanel is the inventory UI mod, OpenKeep and ECR add no UI of their own): `PackPanelOwner` finds PackPanel (`milkyteam.packpanel`) in BepInEx's chainloader on first use and reads its `1. Inventory / Enabled`; without it `Column.Active` is false, `Arrange`/`Boxes`/`Add` and `HudRow.Add` change nothing and return false or null, and the game's plates stay as the game draws them. Consumers: PackPanel (moves the container into its own stats panel beside the grid; the library places it only when it makes it, so the move holds), GrindstoneSkills (word tips in its skills panel's info pane, `LinkTips`), EliteCreaturesReborn (world tier, rank 400, only with PackPanel); in the HUD column PackPanel's armour (rank 100) and weight (rank 300) and ECR's world tier (rank 400). OpenKeep (since 1.11.0) uses only `DressTooltip` and `EmbeddedSprite`: its trash can is its own copy of the game's armour plate named `Trash`.
- `TraitSets/`: `TraitStore<T>` (bit mask + primary key in a ZDO), `TraitRoller` (weighted roll, roll many with declining chance).
- `YamlConfig/`: `YamlModel` is the base a mod derives from (`Read(YamlNode root)`, `Verify()`; `Errors` reject the files, `Warnings` do not; `ReadGroups`/`ResolveGroups` via `YamlGroupTable` for the common `groups:` map). `YamlNode` is one value of the parsed tree: `Get` chains through missing keys, the typed `Try*` readers report with the YAML path, `WarnUnknownKeys` flags keys nobody asked for. `YamlFileSet` describes one `Name*.yml` family (model factory, apply callback, default content, sync key). `YamlFileHub` owns the sets: registration, one Charter `Article<List<string>>` per set for the server push, build and apply, write-back on the author, `HookGame` (load at menu or dedicated start, apply at first spawn). Its internals are split into `YamlFileStore` (discovery in the search folders, reading, default content, atomic write-back), `YamlFileWatcher` (five-second poll reload on a timer thread, handed to the main thread), `YamlGameHooks` (the three Harmony patches, installed once per assembly) and `YamlFileList` (the path/content list shape of the article). `YamlEditorWindow` is the IMGUI editor with live validation and save/apply/discard.
- `SyncedConfig/`: `SyncedConfiguration` facade over Charter, ConfigReload and YamlConfig.
- `PatchGuard/`: `Guard.Install(harmony, log, assembly)` records the mod's logger and assembly (it patches nothing and returns 0). `Guard.Run` / `Guard.Wrap` run an entry point and, when it throws, walk the exception's stack; when the mod assembly (or one of its root namespaces, from the trace text) is on it, the exception is logged under the mod's logger with the given context, then rethrown. `Guard.Report` only logs. `Profiler.Install` times every method the mod patched and reports the most expensive ones. Call Install last in Awake.

## Rules

- Public API changes must keep every consuming mod compiling (EliteCreaturesReborn, EliteCreaturesPack, FeastMaster, Lockstep, OpenKeep, PackPanel, ShipConfig, EarthWright). Build the mods after touching a library.
- Keep game coupling minimal and explicit. `YamlGameHooks` (behind `YamlFileHub.HookGame`), `TraitStore`, `ItemCopies`, `BundlePrefabs`, `LocalEffects`, `PlayerGrid`, `Hotkeys` (`Chat`, `Console`, `TextInput`, all public), `WindowInput` and `MapClicks` (private members by name) are the only places that touch game types on purpose; use reflection (`AccessTools.Field`) instead of publicized assemblies so consumers do not need a publicizer for the library's sake.
- `YamlNode` readers are generic (scalars, lists, maps, enums): no mod vocabulary in the library, neither a consumer's domain nouns nor its setting names such as "world level"; that belongs in the consumer's `YamlModel`. Docs and examples use neutral words (rules, tags, tools).
- `YamlModel` reports problems through `Errors` (files are rejected, the previous configuration stays) and `Warnings` (files are applied). Use the right one.
- Consumers merge these DLLs with ILRepack `Internalize=true`; do not rely on public types being visible across mods.
